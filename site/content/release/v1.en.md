**Draft notice** — This page is an unpublished 1.0 review draft. Krizaka Agents is our own private engineering system, used internally every day; there is nothing to buy or to request here, and no release date is promised.

See also the companion [environment migration draft](/migration/) for the full variable rename reference.

### § 1 — System context

Krizaka Agents sits around coding sessions so work moves from an issue to a checked, merged pull request under clear boundaries. The context diagram below is generated directly from the system's architecture model.

<!--release-view:v1_c1-->

### § 2 — Ports and adapters

Version 1.0 separates core workflow logic (session builder, commands, trains, coordinator, watchdog) from external dependencies through typed service ports. Configuration and environment validation sit at the startup boundary so drift fails early.

<!--release-view:v1_c2-->

### § 3 — Supervision and the tower

Scheduled scans, the watchdog, the operations service and the local cockpit watch sessions, trains and alerts without letting a model decide when an alert closes.

<!--release-view:v1_tower-->

### § 4 — One event format, one sink

Every session, command refusal, train step and alert writes to one structured event schema into one operations sink, with OpenTelemetry log export to observability.

<!--release-view:v1_events-->

### § 5 — Real measures, with sources and context

Every figure below is read from dated command outputs stored in site data rather than typed into prose. Where a figure is unavailable in the snapshot, the page marks it unavailable.

### § 6 — Migrating environment names

Every configuration variable is moving from old organisation prefixes and vendor words to role-named prefixes. Existing names are accepted through the alias table with a deprecation warning for one release window before refusal.

Browse every old-to-new mapping on the [environment migration draft](/migration/).

### What is not proven yet

- Automated tower runs under steady load remain at zero in this snapshot and have no post-change comparison yet.
- The daily alert target has not yet been re-measured across a full lane-on window after tuning.
- CI minute totals are not captured by the local watchdog export and are omitted rather than estimated.
